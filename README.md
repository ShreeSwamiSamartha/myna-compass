# Myna Compass

Build a polished, executive-level web prototype called:

“MYNA PRODUCT DECISION & IMPACT SYSTEM”

Purpose:

This is NOT a live analytics dashboard and must NOT present invented numbers as Myna's actual data.

It is a Product Lead prototype showing how I would help Myna Mahila Foundation make better product decisions by connecting:

1. Field/user reality

2. Donor/grant commitments

3. Engineering/technical reality

4. Product strategy

5. Measurement and impact

6. Privacy/consent constraints

7. Research evidence

The prototype will be shown to a senior advisor/former IAS officer in a 20-minute interview. It should communicate strategic thinking, prioritization, intellectual honesty, and execution discipline.

IMPORTANT:

Do not fabricate Myna operational metrics.

Do not imply that illustrative numbers are real.

Where data is unavailable, display:

“TBD — requires Myna data”

or

“Not currently available”.

Clearly distinguish:

- Myna/team-reported information

- external/proxy evidence

- hypothesis

- missing data

- illustrative examples

DESIGN:

- Premium, minimal, professional executive interface

- Not flashy

- Not a generic SaaS dashboard

- Excellent typography

- Strong whitespace

- Clean cards/tables

- Easy to understand in 5 seconds

- Desktop-first but responsive

- Avoid excessive charts

- Use restrained colours

- Make the product feel like a strategic operating system rather than an analytics toy

NAVIGATION:

Create exactly 5 primary tabs:

1. EXECUTIVE

2. JOURNEY

3. ROADMAP DECISION ENGINE

TAB 4 — DATA CONFIDENCE

--------------------------------------------------

Title:

“Evidence & Data Confidence”

This tab is designed to prevent false precision.

Create four evidence levels:

VERIFIED

Directly available from Myna systems or validated internal data.

PROXY

External research/population data used because Myna-specific data is unavailable.

HYPOTHESIS

Strategic assumption requiring validation.

MISSING

Myna currently does not capture the required information.

Create example rows:

Metric | Status | What we know | What is missing | Next action

Latency

Status: MISSING

What we know: Team reports latency / blank-page issues

Missing: Actual latency/error distribution

Next action: Instrument backend + frontend events

Referral completion

Status: MISSING

What we know: Referral capability exists in some journeys

Missing: End-to-end completion measurement

Next action: Instrument referral funnel

Anaemia prevalence

Status: PROXY

What we know: External Maharashtra evidence may provide population-level context

Missing: Myna-specific prevalence

Next action: Compare with programme baseline

Vitamin D

Status: HYPOTHESIS

What we know: Potentially measurable through before/after testing

Missing: Strategic priority, prevalence, intervention feasibility and Myna capability

Next action: Compare against alternative pathways

Clinical outcome

Status: MISSING

What we know: Behavioural/product data is easier to collect

Missing: Consent-aware longitudinal outcome linkage

Next action: Define privacy-preserving measurement architecture

Create a prominent statement:

“I would rather show ‘data unavailable’ than manufacture precision.”

Also create:

“Measurement architecture”

Aggregate behaviour

→ Pseudonymous journey continuity where legitimately permitted

→ Consented service linkage where appropriate

→ Research cohorts / RCT evidence

→ Outcome measurement

Include a privacy note:

“Do not assume anonymity makes measurement impossible, and do not assume identity linkage is automatically permissible. Validate the legal, consent and technical architecture before implementing longitudinal linkage.”
